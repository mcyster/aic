# CLI-First Surface

These are early design notes, not a settled specification.

## Direction

`aic` is CLI-first. It uses the existing shell as its user interface rather than embedding a terminal chat application or full-screen TUI. One invocation represents one conversational turn.

The durable abstraction is the conversation, separate from the local CLI or agent process. Agent execution may eventually be local or remote, foreground or background, without changing the conversation model.

## Surfaces

Surface is a first-class concept, separate from conversation and agent execution. Console is the first surface. JSON is the likely second surface for structured composition and clients.

For the console surface, explore these visual markers:

- `#> ` for agent or model metadata
- `## ` for commentary or progress
- `#$ ` for commands
- Completely raw subprocess output
- Unprefixed final conversational output

The console surface should render these markers. They should not be generated by prompting the model, because presentation belongs to the surface rather than the conversation.

## Unix Composition

Preserve normal shell composition. A likely future contract is:

- Standard output contains the final result.
- Standard error contains execution progress, commentary, and tool activity.

This separation would allow pipes and redirection to consume the conversational result without suppressing execution visibility.

## Other Clients

Richer editor, web, or Slack interfaces should be clients layered over the same conversation model. They may render the conversation and agent activity differently without changing their underlying semantics.
